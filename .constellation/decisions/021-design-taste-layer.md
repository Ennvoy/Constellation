# 021 設計品味層落地：廢除 150 套資產庫、design 兩條路並列、新增 design-taste.md

> ②「定版點一字未動」已 superseded by 023（P5）。

背景：使用者要求安裝第三方 skill github.com/leonxlnx/taste-skill，盤點後發現那是 13 個 skill 的合輯（10 個出 code、3 個只出參考圖），核心價值集中在「版面構圖的量化硬規則」與「AI 破綻鑑識清單」兩塊。初步評估曾以「本 repo 已有 150 套品牌設計系統資產庫覆蓋風格層」為由主張不必搬，使用者當場推翻：「品牌設計庫對我來說有點沒用，實際上我應該也不會真的去看」。順此攤開三件事：①那個庫撐起的是「請使用者挑基底」這個決策點，而使用者手上的專案幾乎都有既有 UI、基底一律取既有 code，庫只在空地專案用一次；②`phase-design.md` 的降級路徑條文自己承認「執行端自己寫的那幾版是同一個判斷的幾種寫法」，而自己寫時手上只有 tokens、沒有任何版面紀律；③使用者另提「design 階段應該可以選 Claude Design 或自己設計」，但憲法 §3 第 8 點把自己寫定性為降級、明寫「走這條等於放棄讓它自己設計」。

決定：三項一起落地。①廢除 `references/design-systems/`（150 套、453 檔、5.7 MB）整個目錄，空地專案的視覺基底改由執行端自己定、不開彈窗——走路徑一挑 Claude Design 內建六套之一，走路徑二依品味條文現場定一組 tokens，兩條都把選定理由寫進定稿記錄，唯一例外是使用者主動點名調性時照做。②憲法 §3 第 8 點從「降級路徑」改寫為「兩條並列路徑，大工程進場彈窗問一次」——路徑一 Claude Design、路徑二執行端自己寫；那句誠實揭露原文保留，但定性從勸阻改為告知；工具四種不可用原因保留，改成「路徑一此刻不可用時只剩路徑二，仍要照實講」；定版點（步驟 5b 使用者在本地跑起來的畫面上親自點過）一字未動。③新增 `references/design-taste.md`（242 行）當設計品味層，`phase-design.md` 在步驟 2、步驟 5 預檢、路徑二三處指名讀取。推薦順序不固定：`grill-close.md` 記 `是（架構有得選）` 推路徑一、記 `是（照既有架構做）` 推路徑二、rework 型畫面一律推路徑二。

原因：庫被廢是因為它的成本不在檔案體積而在那個決策點——把使用者拉來回答一個他不想回答的題，正撞 §0「機制省下的時間要超過它消耗的時間」。品味層要補的是設計系統管不到的一層：150 套那種 9 段 DESIGN.md 顆粒度停在「按鈕圓角 6px」，管不到「hero 塞了七樣東西、八個區塊有五段都是左字右圖」；品味條文只收能被眼睛數或被 grep 出來的規則，數不出來的品味描述一律不收。兩條路能並列的前提正是品味層存在——沒有它，路徑二就只是「沒有紀律地自己寫」，不夠格跟路徑一並列。品味條文另開適用範圍分流（行銷頁全套適用、後台介面只取內容破綻與無障礙狀態那幾章），因為本專案多數是後台系統，把版面變化度硬加在後台只會把好用的介面改難用。

證據：三次彈窗拍板——「品牌設計庫這個決策點怎麼處理」選「把 150 套整個清掉」（另兩個選項是「我自己挑不問主人」與「降為點菜字典」）；「design 階段路徑選擇」選「改成兩條並列，進場問一次（推薦）」（另兩個選項是「預設自己寫、Claude Design 降為選配」與「不動憲法只補品味條文」）；「生圖要不要做」使用者澄清真實需求是「生背景圖、插圖等網頁素材」而非設計方向參考圖，並指示「生圖優先用 codex，api 可以當作備案」。第 6 章圖像素材的規格全部來自實測：`codex exec --skip-git-repo-check` 在 Claude Code 端非互動生圖成功（exit 0，圖片落地 2048×1152）；內建工具不吃精確尺寸參數，要 2048×1152 實際生成 1672×940 再被重採樣放大；中性需求（「深色沉穩、抽象資料流動」）直接生出藍色發光粒子波浪加網格連線的科技股票圖，正好命中品味條文 1.1 節禁止的 AI 指紋，證明規矩該管的是需求怎麼寫而非工具怎麼叫；PNG 轉 WebP 實測 3.0 MB → 84 KB（quality 82，剩 2.7%）、213 KB（quality 95）。生圖管道盤點：Codex 內建 `image_gen` 免 API key 走訂閱額度、原生支援去背；OpenAI/Gemini API 那條本機三層環境變數與所有 `.env` 位置均無金鑰，Python 套件已備齊，補上金鑰即可用；本機無離線生圖管道。taste-skill 未收錄的部分：訪談步驟與三旋鈕（跟本專案訪談階段搶位置，且其「一次問一題用自然語句」與本專案「一律走彈窗」衝突）、企業設計系統對照表與 npm 安裝清單、字體色彩深色模式通則（會跟專案既有 token 打架）、參考詞彙表、Block Library 空殼、Apple 玻璃感 CSS、output-skill（與設計無關）。
