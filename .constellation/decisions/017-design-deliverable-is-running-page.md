# 017 — design 的交付物改成「使用者在本地點過的正式畫面」

- **狀態**：已拍板（2026-08-13，使用者當場修訂憲法）

## 背景

`crm-system` 專案的使用者走查發現：2026-08-01 在 Claude Design 上談定的「單一活動」四個子分頁
（數據分析／稽核複核／調整紀錄／定案），與線上實作**四頁都不一樣**——12 個區塊沒有任何決議說要拿掉
卻無聲消失（獎勵發放的兩張逐日發放表、稽核的規則卡與左右雙欄複核版面與必填檢核清單、調整紀錄的
趟次層／日層兩張分表、定案軌跡與 30 天強制定案警語、單一司機的稽核標記紀錄、隊員清單的排序與分頁、
子分頁籤上的數字）。

實查因果鏈（證據在該專案 `decisions/075`、`decisions/153`、`archive/2026-08-03-*/tickets/T-011`）：

1. design 階段的**離場條件沒做完就過關**：那一輪 `_v2/` 只留一個空資料夾、該輪連
   `design-frozen.json` 都沒有，等於「轉譯落地」與「定稿即凍結」兩步都沒發生。
2. weave 進場**只驗「有沒有定稿決議這筆檔」**，決議寫得漂亮就放行。
3. 定稿記錄的顆粒度只到「有哪幾個區塊」，於是拆票時「獎勵發放裡面長什麼樣」無處可轉譯，
   該票 14 條驗收條件裡**一條都沒提到它**；另三頁被寫成「內容與 T-007／T-008／T-009 的**行為一致**」，
   那句話寫下的那一刻三頁的版面就沒有人負責了。
4. 八天後（2026-08-11）使用者抓到過一次，但那次走查只比到**區塊標題**層級、還查錯了設計稿專案
   （誤判「舊稿已被覆蓋、看不到了」，實際上稿一直都在），於是用錯的前提結案。

**病根不在執行不力，在條文本身**：舊條文把使用者的拍板放在 Claude Design 的 canvas 上（§3 第 3 點），
而「轉譯落地」後只要求**執行端自己**跑一次看一眼（`phase-design.md` 步驟 5），凍結也由執行端自己寫。
定版的簽名簽在稿上，落地與凍結全發生在使用者視野之外——**做沒做他都看不到**。

## 決定

**design 的交付物＝專案裡真的改好、能用瀏覽器打開點完的正式畫面**；「canvas 上的稿」與
「元件檔案存在於 repo」兩者都不算定稿。五項配套：

1. **新增步驟 5b（唯一的定版點）**：改完正式頁面 code → 開本地 dev server → 把網址交給使用者、
   列出請他看的頁面與互動 → **他親自點過並拍板**才算定稿。不可代為拍板、不可用截圖替代、
   不可跳過去寫定稿記錄。canvas 那一步（步驟 3）降級為「設計方向確認」，明文寫「不算定版」。
2. **改的是正式檔案、正式路由**：不掛暫時網址、不開 `?variant=`、不做預覽區、不另建假資料檔層
   （獨立假資料檔會進凍結名單，刪它還要先解凍）。**保險是 git**。後端已存在就直接接真 API，
   還沒有才把最小範例值寫死在元件裡、build 換掉。
3. **weave 進場改機器三驗**：定稿記錄（含逐區塊元件清單與本地拍板紀錄）／`frozen` 非空／
   名單每個路徑真的存在於 repo。任一不成立就是沒定稿、退回 design 並講明哪一條沒過。
4. **定稿記錄必須附逐區塊元件清單**（畫面→區塊→區塊內部元素與互動，從 code 機械抽出，禁散文），
   並在 `design-frozen.json` 加 `source` 欄（projectId ＋ 取用檔名）。weave 另加禁令：
   **驗收條件不得用「與 X 行為一致」涵蓋畫面**，畫面一律逐區塊寫。
5. **閘門 3 兼任哨兵**（不是第六個閘門，是既有閘門加一段讀檔）：`grill-close` 記著需要 UI、
   且已有定稿記錄時，開場順手驗上述三項，不成立就印醒目警示與處置步驟。

**雙 runtime**：5b 的主體（起本地 server、使用者拿自己的瀏覽器點）**與 runtime 無關、兩邊一樣、不降級**；
只有「交件前執行端自己預檢畫面」那一小步降級——Codex 端裸 CLI 沒有內建瀏覽器（§11.5 實查），
改以「HTTP 回 200 ＋ 關鍵區塊標記出現在 HTML」＋元件 render 測試代替，並**誠實講明沒親眼看過**。
拍板的提問形式照既有降級表（Codex 走文字點列），拍板這件事本身不打折。

## 原因

使用者原話（2026-08-13）：「我是要做出真正的 UI 而不是還是定稿而已，等於我要你把對應畫面的 UI
真實做出來網站，後面才開始接後端」、「你就要直接動手改了，改完以後開本地給我確認畫面，我同意之後
你就接 API 這樣，反正我們不是有 git 版控，不行再復原」。他並指出這正是 Constellation 建立當初就
要求過的事——實查母本原文，**要求只落實了前半**（§1 與 §3 第 5 點確實寫了「一次性轉譯落地」），
「才能定版」那半段落錯了位置，故本次補上。

代價已誠實記入 §11.5：每輪 design 多一次「等使用者有空點」的來回，流程變慢；刻意付這個錢。
另揭露一條刻意未補的缺口——「上一輪定稿過、這一輪不見了什麼」的跨輪比對還沒加，它要等逐區塊清單
累積過一輪才有基準，下一輪再評估。
