# 014 移除 CLAUDE.md／AGENTS.md 提議機制

背景：原機制寫在三處——DESIGN.md §4（憲法）、phase-ship.md 步驟 3（ship 收尾彈窗提議）、gates/session-start.mjs（開場注入附一行提醒）。立意是 CLAUDE.md 為 runtime 原生每場 session 必讀，等於在 `.constellation/` 注入之外多一層零成本接續保險。

決定：三處全數移除。ship 收尾不再提議生成，session 開場不再印提示行，機制完全下架。DESIGN.md 母本 repo 結構樹描述本 repo 自身檔案的那行不在移除範圍。

原因：條文原本寫「使用者不要就算了，不強推、下輪 ship 再提」——「下輪再提」等於每輪出貨固定重問一次，加上開場提示行，一輪打擾兩次；機制本身無記憶、無法反映使用者已表態。使用者明示不需要此提議，保留一個已被拒絕的功能只是持續消耗注意力。同場否決的替代方案：「拒絕後寫記號進 config.json、該專案不再提」——為一個已被拒絕的功能新增狀態欄位與判斷邏輯，比直接移除更複雜，違反極簡原則。

證據：2026-08-10 彈窗「出貨時問要不要生成 CLAUDE.md……要怎麼拿掉？」使用者於彈窗中選擇「整條拿掉」選項，否決「只拿掉出貨彈窗」與「改成拒絕就不再提」兩案。
