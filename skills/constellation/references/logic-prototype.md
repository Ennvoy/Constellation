# 邏輯原型（單檔 HTML 拋棄式樣品）

> 改寫自 prototype/LOGIC.md 精髓，貼合 Constellation。適用時機見本檔同目錄 `phase-grill.md`「邏輯原型繞道」——只在「文字講不清＋選錯代價高」的狀態機／資料模型題動用，不是每題都做。

## 它是什麼

一個雙擊就能開的單一 HTML 檔（無框架、無安裝、全部 inline），使用者按按鈕看狀態變化，用來在拍板**前**抓出想法本身的 bug——「等一下，這不應該發生吧」那一刻就是它的全部產值。

## 規則

1. **問題寫在最上面**：頁面頂端一段話寫清楚「這個樣品在驗什麼問題」——答錯問題的樣品是純浪費，寫明才對得了帳。
2. **邏輯與頁面分離**：把要驗的邏輯寫成純函式／狀態機（reducer 形態 `(state, action) => state`，或明確的狀態轉移表），放獨立 `<script>` 區塊、不碰 DOM；頁面只負責呼叫它、渲染狀態。拍板後這段邏輯可直接搬進正式 code，頁面丟掉。
3. **全部用域語言**：按鈕與狀態欄位照 `CONTEXT.md` 的詞彙寫（「取消訂單」，不是 `dispatch(CANCEL)`），使用者不用懂 code 就能玩。
4. **版面固定三層**：
   - 標題＋一句話說明（第 1 條那段話）。
   - **現況狀態面板**：欄位化呈現（不是 JSON 傾倒），每次點擊後重繪，標出剛剛變了什麼。
   - **自由操作按鈕**（每個動作一顆、隨時可按、任意順序）＋**情境走查 tabs**（2–3 個；每個 tab 一段白話情境說明＋照順序按的按鈕，走查開始時重置到已知初始狀態）。情境專挑紙上最難想的：一條 happy path、一個刁鑽邊角、一個「應該要被擋下」的非法操作。
5. **不加測試、不接真 DB、不通用化**：它是樣品不是產品；狀態活在記憶體。
6. **收尾**：使用者玩完、彈窗拍板後——結論落 decisions/（證據欄寫原型結論），樣品檔留在暫存目錄自然消失，不 commit、不進 repo。（與 mattpocock 原版「留 prototype 分支當 primary source」刻意不同：決議檔已載結論，樣品閱後即焚，不新增要維護的檔案。）

## 反模式

- **樣品越做越像產品**（加樣式細節、加錯誤處理）——它只需要能玩。
- **邏輯散進按鈕 handler 裡**——那段邏輯就搬不回正式 code 了，頁面永遠是殼、邏輯永遠是核。
- **拿樣品驗「畫面好不好看」**——那是 design 階段的事，這裡只驗行為與資料形狀。
