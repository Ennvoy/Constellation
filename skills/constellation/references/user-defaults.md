# 使用者開發預設（訪談與拆票的預設推薦）

> 這是使用者的既有習慣，訪談時當**預設推薦**帶入——不要當成不能改的鐵律，
> 使用者當次明示可推翻；但也不要當沒看到、每次重新從零問起。

## 技術棧預設

- **前端部署**：Railway。
- **後端**：Supabase（資料庫＋Auth）。
- 訪談問技術選型時，直接以上述為推薦選項（「預設照舊用 Railway＋Supabase，要換嗎？」），
  除非任務性質明顯不適用（如純 CLI 工具、本機腳本）。

## Web 系統必備四模組

開發**網頁系統**時，以下四個模組是使用者的固定需求，缺一不可：

1. **使用者管理**——註冊／登入／帳號管理，預設用 **Supabase Auth**。
2. **角色管理**——可定義角色（如 admin／manager／user）並指派給使用者。
3. **權限管理**——功能與資料的存取控制對應到角色。
4. **使用紀錄**——誰在什麼時候做了什麼的 audit log。

### 對流程的意義

- **phase-grill（訪談）**：web 系統任務不必問「要不要使用者管理」——直接當已知需求，
  訪談聚焦在「這次系統有哪些角色、各自能做什麼、哪些操作要留紀錄」這種任務特定細節。
- **phase-weave（拆票）**：web 系統拆票時對照四模組清單——每個模組都要有對應的票
  （或明確併入某張票的驗收條件）；若使用者當次明示某模組不要，在 grill-close.md 記一筆再省略，
  **不得默默漏掉**。
- **高風險標記聯動**：含使用者／角色／權限管理的系統天然「涉權限」——grill-close.md 的
  高風險標記照規則標「有」，出貨審查自動加開 security 紅軍軸。
