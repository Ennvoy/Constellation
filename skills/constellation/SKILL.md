# Constellation 總控

本檔做的事：**先判這件是不是流程外，不是就偵測現況、決定接到哪一步、Read 對應的 phase 參考檔照做**。五步的實作規則都在
`references/phase-*.md`，本檔不重複——一次只 Read 當下用得到的那一份，其餘四份不預先載入；本檔只放跨階段的紀律（含入口就要用到的「流程外小改動」與「不等進行中的批次」）。

## 五步主幹（一行一步）

| 步驟 | 代號 | 一句話 |
|---|---|---|
| ① 訪談 | grill | 批次問到 frontier 清空，決議即時落檔 |
| ② UI 定稿 | design | Claude Design 自己設計（或執行端自己寫）→ **直接改專案正式頁面 code** → **執行端在本地逐一點過、整頁截圖交使用者看圖拍板**（缺工具時退回使用者自己點）→ 才算定稿（真數字／後端後接）|
| ③ 合成拆票 | weave | 不再發問，把決議合成任務卡＋垂直拆票（驗收條件、依賴關係） |
| ④ 逐票實作 | build | 無依賴票平行 fan-out、序列整合，每票測試先行→實作→實跑驗證→關票；每批整合完跑一次獨立審查、同批結案 |
| ⑤ 出貨 | ship | 全量真鏈路驗證＋獨立各軸審查（Standards／Spec 分開報告，只看跨票與整體） |

## Step 0：偵測現況（流程外判定之外，純檔案存在性判斷，狀態進檔案不靠對話記憶）

`.constellation/next-round/` 不屬於本輪，以下判斷都不看它——那裡放的是使用者選了「下輪做」的待辦票，不管有沒有票、幾張，都不影響現在該接到訪談、拆票、實作還是出貨哪一步。

**先判流程外（任何現況下都先做，決議 032）**：使用者這次要的是一個連貫的小改動時，先讀要改到的檔案，對照下方紀律「流程外小改動」的「不算流程外」條件判定；符合就彈窗確認一次「這件走流程外」（使用者點一下即可），照該紀律辦，不進下面的路由，也不跑訪談的開工前盤點、筆數查詢與設計樹。不符合或使用者不同意，才往下依序檢查。進行中的輪次不影響這個判定（不等它，見紀律「不等進行中的批次」）；但進行中輪次自己的修正（審查或紅燈的發現、使用者選「現在做」的事、這輪票範圍內的調整）不算流程外，照該階段規則做。

依序自行檢查：

1. **cwd 下沒有 `.constellation/`** → 全新任務，尚無任何決議。
   Lazy Read `references/phase-grill.md`，從頭開始訪談。

2. **`.constellation/` 存在，但 `tickets/` 不存在或裡面沒有任何 `*.md`**：
   - `decisions/grill-close.md` 不存在 → 訪談尚未完成——**即使 `CONTEXT.md` 或 `decisions/` 底下已經有其他內容也一樣**，這份固定決議檔是唯一的機讀完成標記，沒有它一律判定訪談未完成，不能拿其他檔案有內容來腦補「應該問得差不多了」（`decisions/` 有內容不代表訪談開過：「拍板即落檔」通則下，流程外的平時討論也會合法落 decisions/——那些是既有決議背景，不是訪談進度）。
     Lazy Read `references/phase-grill.md`，走增量重訪（機制會自動判斷從哪接，不會重問已拍板的節點）。
   - `decisions/grill-close.md` 存在、記著大流程，但檔尾沒有「盲點審：已收斂（第 N 輪）」這一行（使用者喊停時寫成「盲點審：使用者喊停（第 N 輪）」，效力相同）→ 訪談收尾已拍板，但獨立盲點審還沒跑完（例如跑到一半換了 session）。不得因為看到 grill-close.md 就當盲點審已經跑完：Lazy Read `references/phase-grill.md`，照「完整性四保險」第 3 點接回盲點審，收斂後才進 `references/phase-design.md`／`references/phase-weave.md`。
   - `decisions/grill-close.md` 存在（內容為大小流程、是否需要 UI、高風險標記、必備模組排除、一句話任務摘要五欄；大流程檔尾另有盲點審收斂那一行；`next-round/` 有票且這輪對它們有任何決定時，檔尾另有「下輪待辦」那一行）→ 訪談已完成、尚未拆票。
     Lazy Read `references/phase-weave.md`；若該任務需要 UI 定稿而尚未定稿，weave 會據此轉交
     `references/phase-design.md`，照它接手即可，不必在此另行判斷。
     ⚠ **「已定稿」不是看有沒有那筆定稿決議就算**——weave 進場要過機器三驗（定稿記錄含逐區塊元件清單與拍板紀錄，記錄裡會註明走的是哪一種：Artifact 連結＋逐互動結果，或使用者拍板回覆原文／`design-frozen.json` 的 `frozen` 非空／名單每個路徑真的存在於 repo），任一條不成立就是沒定稿、要退回 design 補做。這三條純檔案檢查、兩個 runtime 都一樣，細節在 `references/phase-weave.md` 進場條件。

3. **`tickets/` 底下有 `*.md`**：
   - 先讀 `.constellation/config.json` 有沒有 `"approved": true`：**沒有**（欄位不存在或為 `false`）→ 代表這批票是 weave 合成出來的，但使用者核准確認那一步被中斷、還沒走完（機讀核准標記見 DESIGN.md §4）。向使用者說明目前看到的票清單摘要，Lazy Read `references/phase-weave.md`，回到「完成後：呈交票清單摘要」那一步重新請使用者核准確認，不能跳過核准直接當作已進 build。
   - **有** `"approved": true` → 照票的 `status:` 欄位判斷：
     - 任一票 `status: open` 或 `in-progress` → 向使用者報告現況：列出每張票的名稱與狀態，
       in-progress 的票額外摘要做到哪（讀該票「決議記錄」段落）。
       Lazy Read `references/phase-build.md`，接續實作。
     - 沒有 `open`／`in-progress`，但有票 `status: blocked` → 向使用者報告被什麼卡住
       （讀該票「決議記錄」找卡住原因；`blocked-by` 欄位空著代表卡在大事待決或真依賴未就緒——原因見決議記錄，不是在等別張票；`blocked-by` 有填票號才是卡在依賴鏈，等那張票 `done` 才會解除）。
       Lazy Read `references/phase-build.md`，照其 blocked 彙整規則處理（大事分歧統一彙報、彈窗請使用者拍板）。
     - 全部票 `status: done`：
       - 讀 `.constellation/ship-report.md`：**存在**、且它「做了什麼」段落第一行列出的票號**涵蓋現行 `tickets/` 底下全部票** → 代表本輪已經出貨過。向使用者報告「本輪已出貨」，新需求視為全新任務；順手補跑一次 `references/phase-ship.md` 步驟 3 把這批舊票歸檔清乾淨，歸檔完成後 Lazy Read `references/phase-grill.md` 從頭訪談，不要誤判成「還要準備出貨」而卡在原地重跑一次 ship。
       - 否則（檔案不存在，或票號沒涵蓋現行全部票）→ 向使用者報告全數完成，Lazy Read `references/phase-ship.md`，準備出貨——若上輪出貨在中途被中斷，從還沒做完的那個 ship 步驟接續，不重跑已經做完的部份。

## 紀律

- 一次只 Read 對應目前狀態的那一份 `references/phase-*.md`；不得因為「反正都要用」而預先讀其餘四份。
- 路由判斷（流程外判定之外）完全依賴 `.constellation/` 目錄下的檔案內容，不依賴這次對話之前聊過什麼——換一個全新 session 進來，讀檔結果必須一樣。
- 大小分岔（大流程完整走②③④⑤；小流程只在③不拆多票、weave 直接產單一任務卡，之後走輕量⑤）由 `references/phase-grill.md` 在訪談收尾時與使用者一次拍板，本檔不重複判斷（流程外例外：入口就由本檔 Step 0 開頭判定）。是否需要②（UI 定稿）與大小流程正交、分開決定——不是「小流程＝連②也跳過」。
- 若讀到的現況互相矛盾（例如 `tickets/` 有檔但 `CONTEXT.md` 不存在），照實告知使用者看到的落差，不自行腦補跳過。`tickets/` 有票卻沒有 `decisions/grill-close.md` 也算這種矛盾（這批票沒經過訪談收尾）——例外：出貨歸檔做到一半（`ship-report.md` 已涵蓋現行全部票，照 Step 0 第 3 點補跑歸檔即可）。這句攔不住刻意繞過流程直接開票（例如正式站出事時的緊急作戰，案例見決議 024），只擋無心漏掉的訪談收尾。
- **發現當場結案，不往後丟（不分階段的通則，決議 031）**：訪談、實作、審查、出貨、上線後檢查，任何時候發現問題，先分「誰該決定」：
  - **執行端能決定的**（程式品質、小 bug、測試、註解、用詞）→ 當場修掉；或判斷不值得修就丟掉，在票的「決議記錄」（出貨階段則是出貨報告）寫一句理由。**永遠不開票**。
  - **要使用者決定的**（方向、權限／個資範圍、新功能、使用者看得到的行為改變）→ 當下用 AskUserQuestion 問，一次一題，選項含「現在做／不做／下輪做」，照答案處理；屬取捨型拍板就照下一條落檔。
  - **途中看到的既有問題**（不是本輪造成的）→ 當下問使用者「現在修／記進 MAP 已知缺口」；記進 MAP 的條目開頭標「（待選）」，下一輪訪談開工前盤點時端給使用者選（見 `phase-grill.md`「開工前盤點」）。
  - **`.constellation/next-round/`（下輪待辦）唯一入口＝使用者在彈窗親口選「下輪做」**：執行端、審查員、指揮官都不得自行把事項開成下輪票；開票時目標段附當時彈窗題目與所選選項原文。不要改寫成一段文字候選清單留在票面、決議或報告裡——那種清單會跟著所在檔案一起被歸檔，下一輪看不到（案例見決議 027）。
- **拍板即落檔（不分階段的通則）**：任何階段——訪談、實作、出貨、乃至流程外的平時討論——只要使用者做了**取捨型拍板**（彈窗選了方向、文字明確拍板），就即時寫一筆 `.constellation/decisions/NNN-slug.md`：背景＋決定＋原因＋證據各 1–2 句，證據記拍板脈絡（彈窗題目與所選選項原文，或使用者原話一句）與當時依據（實測數據、文件連結；沒有就寫「無」）。純事實（查得到的）與實作小事（記入票的決議記錄）不落 decisions/，防流水帳。落了檔，下個 session 開場注入就會端上桌——「討論好的決議隔天就忘」正是靠這條根治，不落檔等於白討論。
- **等別人時，背景要有東西會自己結束並叫醒你**：結束回合前若在等另一個 session（機器鎖被佔用、對方全量還沒跑完；別批還沒上線不算要等的事，見下方「不等進行中的批次」），背景必須有一個會自己結束並主動叫醒你的東西——排隊中的驗證 runner（見 `references/phase-ship.md` 步驟 1）是最常見的一種，其餘背景任務比照辦理；正文寫明是靠哪一個叫醒、最晚幾點該回報。**沉默不算同意，閒置不算做完**——不得只寫「等對方通知」就把回合結束掉。
- **流程外小改動（決議 032）**：一個連貫改動、主線或單一工作流做得完，入口就判定（見 Step 0 開頭），不進五步主幹、不寫 `grill-close.md`、不建 archive：
  - **不算流程外**（對著 diff 判，碰到任一項就不是）：資料結構（migration、資料庫 schema 或 ORM 模型、會被存下來或跨模組傳遞的資料格式、共用型別與 API 契約）；RLS、policy 或權限判斷；金流計算、個資的讀取範圍或輸出；新增或升級套件；全域設定（建置、框架、middleware、全域樣式）；部署、連線、環境變數、憑證設定；這次動作本身要寫入或回補正式資料（一次性腳本、回補、手動改資料）；Constellation 的閘門程式行為或 hooks 設定（只改註解不算）；凍結名單內的檔案（另開工作區時看主工作樹那份 `design-frozen.json`）；改到的查詢或寫入碰到 `MAP.md` 記為超過大量資料門檻或會隨時間長大的表。另在入口看使用者這次的話判斷：做法有兩種以上、會讓使用者看到不同結果、而使用者還沒選定，也不算。做到一半才發現碰到了，當場升成小流程（Lazy Read `references/phase-grill.md` 照小流程走）。
  - **驗證**：全域靜態檢查（typecheck、lint、build；build 在另開的工作區跑，或確認沒有別人的站在用同一個建置目錄時才在主工作樹跑）＋改到的檔案所屬的測試子集（挑法同 `references/phase-weave.md` 的票級「驗證指令」縮圈），直接用測試框架跑；不跑出貨全量。子集含 e2e 或資料庫測試時照決議 026 的退讓做法：用自己經 `gates/serve.mjs` 起的站、只跑子集，不跑整套。
  - **先給使用者看，再審、再上線**：看得見的改動起本地站截圖、發私人 Artifact；給人讀的產出（週報、推播、報表文字、口徑數字）套真資料做樣本，照 `references/verification-playbook.md`「測試資料衛生」（唯讀，或帶記號的測試資料）。
  - **一位對抗驗證員**（獨立 context、顯式帶 `model`）：拿使用者這次的原話與相關決議原文比 diff；另查框架執行期陷阱（例如 `'use server'` 檔匯出非函式會讓整頁載入失敗、單元測試因 mock 而全綠）、會不會寫到正式資料、會不會改到別的畫面；邏輯改動要在本地站把改到的路徑真跑一次。只回報寫得出具體後果的阻擋級，當場修。純文案，或只動單一頁面自己的樣式（不動共用元件與全域樣式、不動邏輯與資料），可省這一步。
  - **落檔**：只有取捨型拍板才落決議（照上面「拍板即落檔」），不必每件都落；commit 後在 `.constellation/HISTORY.md` 最上方補一行「`## <日期> <摘要>（流程外，無票）驗證：<相關測試＋結果>；使用者看過：<是／不適用（純後端、無可看產出）>；對抗驗證：<有（N 條）／無（純文案或單頁樣式）>`」——「使用者看過」只有這兩種值，沒有「否」（有可看產出就得先給使用者看過才上線）；「（流程外，無票）」要原樣連在一起寫（要附決議號就寫成「決議 NNN（流程外，無票）」），開場閘門靠這串字把它排除在輪次之外。本檔 Step 0 讀到 `HISTORY.md` 裡 `##` 開頭、內含「（流程外，無票）」的行，不當成未歸檔的輪次——那本來就沒有票、不必也不會有票清單可歸。這次若同時放棄了 `next-round/` 裡的某張票、或那張票剛好被這次改動順手解決掉，同一個 commit 裡把它 `git mv` 到 `.constellation/archive/next-round-closed/`，在落的那筆決議（沒落決議就寫在 HISTORY 那一行）寫明原因（放棄或已被這次改動解決）——不寫這一步，下一輪還是會再被問到那張票，甚至被重做。
- **不等進行中的批次，誰先驗完誰先上（任何工作皆然，決議 032）**：不因別批還沒跑完全量或還沒上線就讓新工作排隊；上線只推自己驗過的那個版本。
  - **推送前兩件事都要成立，不靠記憶**：①正式站回報的 commit（git 部署的專案看健康檢查端點；查不到就以 `git ls-remote <remote> <主線>` 為準，並在正文講明）必須是 HEAD 的祖先；②`git log --oneline <正式站 commit>..HEAD` 列出來的，只能是自己這批驗過的 commit（含併入用的 merge commit）。任一不成立就停下查，不硬推。非 git 部署的專案，部署前先推遠端主線。
  - **另開工作區**：主線上有別批尚未上線的 commit，或主工作樹有不是自己的未 commit 改動（例如進行中輪次訪談、定稿期的決議與畫面改動）時，從最後上線的那個版本另開工作區來做與驗，驗完在工作區裡推（`git push <remote> HEAD:<主線>`）。開之前先 `git fetch`；優先 `git worktree add --detach <路徑> <上線版本>`（不建分支，git 守門不攔；`checkout`、`switch`、`worktree add -b` 會被攔，要開或切分支先彈窗問使用者）；`node_modules` junction 與收法同 `references/phase-build.md`「平行編排」與「保護三」；`.env` 自己複製進去、不 commit；取決議或票號前，同時看主工作樹 `.constellation/decisions/`（含未 commit）與 `git ls-tree --name-only <主線> .constellation/decisions/` 兩處的最大號，免得併回時撞號。
  - **併入後重驗**：自己上線後，另一批要把它併進來；併入後，那批自己當初那套驗證要在新的 HEAD 上重跑才能推——簽過全量全綠的重跑全量、拿同一次完整全綠（同 `references/phase-ship.md` 步驟 1），流程外重跑同一組靜態檢查與子集。推送被 git 以非 fast-forward 拒絕時同此處理。零機制檢查（只適用簽過全量的批次）：推送前若 `git log --merges -1 --format=%cI` 晚於最後一筆簽章時間（`.constellation/ship-evidence.md`，已歸檔就看 `archive/` 裡那份），代表簽章後併入過別批，就要重跑。
  - 機器鎖（`--scope ship` 出貨全量的排隊，見 `references/phase-ship.md` 步驟 1）照舊，不屬於這條拿掉的排隊。
